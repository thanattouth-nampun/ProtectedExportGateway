## Narrow diagnostic command

`MipFeasibility defender-scanner-probe <private-config>` accepts strict JSON (unknown fields reject), synthetic acknowledgment and a nonempty authorization reference. Its example defaults cannot run. It refuses an elevated administrator token. It cannot accept arbitrary files, executable arguments or a user-selected command: it generates exactly one benign values-only XLSX through SyntheticReports, creates a GUID-named file in a reviewed private DACL/reparse-guarded root and holds the bytes read-only throughout the scan.

The executable must be an exact numeric-version MpCmdRun.exe under the OS ProgramData Microsoft/Windows Defender/Platform root, with no reparse ancestor, and match an operator-reviewed SHA-256. Before the actual experiment, Windows Authenticode verified the exact executable as Valid/Microsoft Windows Publisher. The runtime pin is not itself an Authenticode chain verifier; only use a pin independently reviewed from the signed installed binary. No arbitrary binary can be supplied through the browser or scan config.

Fixed ArgumentList: `-Scan -ScanType 3 -File <server-generated-private-fixture> -DisableRemediation`, UseShellExecute=false, CreateNoWindow=true. The fixture is generated internally, never untrusted upload content or protected-source ciphertext. The binary and fixture handles remain read-locked and both are rehashed. Stdout/stderr are drained with a 16-KiB cap each; truncation rejects. Process deadline is 120 seconds, with bounded CLI termination/drain waits. Stopping MpCmdRun does not prove cancellation inside the AV service, so timeout remains native-completion-unknown, retains private fixtures and must not trigger automatic retry. Native timeout/crash lifecycle is not yet live-tested.

Reports always use cleanVerdict=NOT_ESTABLISHED, CanPublish/GatePassed=false and never produce ScanEvidence. Native exit0 is INVOCATION_COMPLETED_UNVERIFIED; changed bytes, truncation, timeout and other exits remain failures/unknown. The raw bounded command text and summary remain private for semantic review. The diagnostic leaves fixtures in the private root; production cleanup/orphan recovery is still required. This tool is not an elevated helper/service or an authenticated IPC boundary, and same-user/privileged-host trust limits apply.

Official [MpCmdRun semantics](https://learn.microsoft.com/en-us/defender-endpoint/command-line-arguments-microsoft-defender-antivirus): custom scans support DisableRemediation; its findings appear in command output, while detection event entries/UI are not emitted for that mode. Exit0 can also mean successful remediation in general. Therefore exit0 or absence of detection events is insufficient release evidence. The documentation calls for elevated invocation; this host's ordinary-token experiment succeeded, which establishes this observed host/build only, not general supported non-admin behavior. No host protection or exclusion settings were weakened.
